Campaign Setup Guide

The one-time org configuration that makes campaigns runnable — email access, sending schedule, AI, enrichment, LinkedIn auto-send, calling, and the extension. Companion to the rep-facing Running Campaigns guide.

01 Overview

This guide covers the one-time org configuration that makes campaigns runnable. Do these once; your reps then work day to day inside the guardrails you set here.

Each section ends with a → Unlocks for reps note so you can see exactly what each switch enables downstream. The rep-facing companion is the Running Campaigns guide, which opens with a checklist mirroring what you set up here.

ℹ️

The help center is role-gated: reps see the Running Campaigns guide, owners and admins additionally see this one. You don't have to distribute anything — the right guide appears for each role.

03 Email access & org outreach limits

Each rep connects their own sending mailbox — this is self-service, not something you do for them. Your job is to make sure they can, and to set the org-wide ceilings.

What the admin does

  1. Ensure the prospecting module is enabled for the reps who need it — that is the access gate. Without it, the sender-accounts screen won't work for them.
  2. (Optional) Set org-wide outreach limits under Org Admin → Sending Schedule / outreach limits — ceilings that apply on top of each rep's own sender caps.

What the rep does (for reference)

🔗
Goes to Settings → My Preferences → sender accounts, clicks Connect, authorizes Gmail or Outlook.
♻️
Reconnects it themselves if it ever shows Disconnected — you are not involved in the refresh.
➕
Can connect multiple mailboxes; the step firer round-robins across all active ones.
ℹ️

Where the daily cap lives: the per-mailbox daily send limit is a property of each sender account (rep-owned), and a campaign's email capacity is the sum of its active senders' limits. You set org-wide limits, not individual mailbox caps.

→ Unlocks for reps: the ability to connect a mailbox and send email. If a rep can't see the sender-accounts screen, they're missing module access — the one thing only you can grant.

04 Org-wide sending schedule

Optional — a default already exists. Campaigns resolve their schedule as campaign → org → built-in default, so outreach still sends sensibly even if you never touch this, and a rep can override the window per campaign.

  1. Open Org Admin → Sending Schedule.
  2. Set the org-wide working days and hours, timezone, and pacing (a fixed interval between sends, or spread across the window). Steps due outside the window wait for the next open slot.
  3. (Optional) Set org outreach limits — org-wide ceilings, in addition to each sender's own daily cap.

→ Unlocks for reps: a good default window. Reps who need something different set a per-campaign schedule themselves — you don't do it for them.

05 AI & the personalization skill

Only needed if your reps use AI drafting. Skip entirely for manual/template-only sequences.

  1. Org Admin → AI Provider Settings — configure a provider/model. Required for any AI drafting.
  2. Org Admin → Prospecting Skill Config — set the guardrails the skill obeys: products, hook ordering, banned phrasings, required disclaimers.
  3. (Optional) Prospecting → Fit Gate Config — restrict AI drafting to prospects that meet your ICP.
ℹ️

If you enable the org policy flags for it, reps can set a personal provider/model or bring their own key; leave those off to keep everyone on the org default.

→ Unlocks for reps: the ability to set sequence steps to AI mode. With no provider configured, AI steps can't draft.

06 Enrichment keys

Only for signal-based campaigns and auto-research. This is the one true admin dependency for signal campaigns.

Org Admin → Prospecting → Enrichment. Add BYOK keys for Apollo and/or CoreSignal. Enrichment fills titles and company data and produces the signals that power signal-based targeting and the Research Queue.

→ Unlocks for reps: decision-ready Research Queue entries and signal-based targeting.

07 LinkedIn connection auto-send

Only if reps will auto-send connection requests. Auto-send is double opt-in: this org switch is step one; each rep must also opt in. Nothing auto-sends unless both are on.

  1. Open Org Admin → Prospecting → LinkedIn.
  2. Turn on connection-request auto-send.
  3. Set the guardrails: the hard rolling-24h daily cap per rep, the working days/hours it may run, and pacing.
⛔

Account risk. Automating LinkedIn actions is against LinkedIn's Terms of Service and carries account risk regardless of guardrails. Keep caps conservative. If you'd rather not take this on, leave it off — reps can still use manual LinkedIn steps (the extension logs everything; they click send themselves).

→ Unlocks for reps: the option to opt in at Settings → LinkedIn Auto-Connect and have queued requests send automatically, with jittered pacing, human-hours gating, and instant challenge-abort.

08 Calling (Twilio)

Only if reps will call. Calling runs on a per-org Twilio subaccount; provisioning it is a one-time step that gates all calling. After that you give each rep a caller-ID number and enable calling for them.

⚠️

Calling is a paid/entitled capability: it stands up a Twilio subaccount and each phone number costs roughly $1/month plus per-minute usage. Confirm calling is in your plan before provisioning.

Provision the subaccount (one-time)

  1. Go to Org Admin → Twilio / Calling Settings.
  2. Click Set up calling (provisions the subaccount + the browser voice app). If it later shows softphone not fully configured, re-run setup to finish enabling the browser softphone.

Choose the calling mode

💻
Browser softphone only (default) — reps talk through the computer over WebRTC; needs only a microphone. No personal phone required.
📱
Phone bridge only — Twilio rings the rep's own phone and bridges the prospect. Each rep must add a personal phone in My Preferences.
🔀
Both — the rep chooses per call.

Recording & per-rep numbers

  1. Toggle Enable recording and Play disclosure announcement (plays a spoken disclosure at call start — leave on where consent requires it). Set rate limits and phone-number format here too.
  2. Give each rep a caller-ID number: Provision a new number by area code (~$1/mo), or Claim an existing Twilio number by its PN… SID (this rewires that number's voice routing to GoWarmCRM).
  3. Enable calling for the rep in the reps table. In bridge/both mode, confirm they've set a personal phone. Release a number when a rep leaves to stop the charge.

→ Unlocks for reps: click-to-dial from any prospect (Call via Twilio), call tasks from sequence Call steps, and outcome logging. Without the subaccount + a rep's number + the per-rep toggle, the calling UI stays unavailable for that rep.

09 Distribute the Chrome extension

For any LinkedIn outreach. The extension (Manifest V3) lets reps capture profiles/companies, log touches, sync connections/messages, and — where enabled — auto-send. Reps install it themselves; your job is to make the build available.

📦
Share the extension build (the folder / zip containing manifest.json) via your install page or directly.
🧩
Reps Load unpacked at chrome://extensions — full steps are in the Running Campaigns guide.
🔐
The extension talks only to your GoWarmCRM app/API and reads the LinkedIn pages the rep visits. No server-side setup on your end.

→ Unlocks for reps: profile/company capture, one-tap logging, and connection/message sync (so LinkedIn replies stop sequences like email replies do).

10 Target Profiles & signal catalog

For signal-based campaigns — but reps can create Target Profiles and add signals themselves, so this is optional curation, not a hard prerequisite. The real dependency is enrichment keys (§06).

📇
Target Profiles — a reusable, org-shared library of ICP definitions under Prospecting → Targeting. Any rep can create one; you may want to seed a few canonical profiles so the team starts from vetted definitions.
📡
Signal catalog — the triggers reps Filter/Prioritize on (a prospect's post, an account event like funding or a leadership change, tech-stack overlap, role + stage curiosity). Reps can pick and add signals; editing inferred mappings and deleting entries are admin-only, so you keep the list clean.

→ Unlocks for reps: vetted starting points in the staged campaign's Targeting step. Reps aren't blocked without your curation — they just build from scratch.

11 Access & visibility policies

Optional. Under Org Admin you can also shape who sees and edits what.

👁️
Prospect ownership / visibility — who can see whose prospects (Mine / Team / Org scope).
✏️
Campaign delete & manager-edit policies — who can delete campaigns or edit others' campaigns.
⤴️
Escalation rules — how stalled prospecting work escalates.

→ Unlocks for reps: the correct scope filters (Mine / Team / Org) and edit permissions across campaign views.
